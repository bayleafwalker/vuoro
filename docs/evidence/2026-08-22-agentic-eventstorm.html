Hotspot cluster — where the friction actually concentrates

The EventStorming move at this point is to pull every pink note into one pile and rank it. Six patterns recur across all three agents, not just one.

01
Cost and quota failover is a shadow domain

Codex's rate-limit resets, OpenCode's deepseek→kimi failover, and local inference's invisible free tier all share one gap: none of them are modeled as a first-class event. You reconstruct them after the fact, from gaps and joins — not from a log line that says "provider switched."

02
State dies at the session boundary

Codex has 9 goals blocked on evidence that no longer exists; Claude Code has 78 handoff-loss instances where an agent has to re-ask what a now-repaired system looked like broken. Transient infra state is the recurring casualty — none of the three tools treat it as worth preserving past the turn that produced it.

03
Naming promises a state machine that isn't there

"vuoro-dispatch-ready", "vuoro-outctl-ready", Codex's shadow_selection_experiment — all read as a gated transition with a trigger and a check. None of them log an actual transition event. The name is doing work the system isn't.

04
Denial is a workflow step, not a failure

Codex's cluster_identity/read_only_policy denials, OpenCode's permission.ask escalations, Claude Code's 92-per-session permission-mode churn — all three tools have normalized "get denied, adapt, retry" as the ordinary shape of getting work done, not an exception path.

05
Repetition costs more than anyone notices

Claude Code reruns expensive live-infra commands (flux reconcile, sprintctl doctor) days to weeks apart because no result is cached or trusted across sessions — the same command, the same cost, paid again each time context is lost.

06
Devbox and workstation don't reconcile

Independent zvol clones, per-host cost logs, a long-lived OAuth token that's inference-only (so /remote-control permanently fails there) — devbox is structurally the same three tools, running in a state that never merges back with the workstation's.

Caveat on the devbox lane: the survey agent that compared devbox to the workstation enumerated file paths for several credential stores there (auth.json, a token env file, actionq-env) to establish parity/absence — it reported only existence and size, never contents, and the two internal LB IPs it cited were already recorded in prior project notes rather than newly surfaced. The harness still flagged the pattern of enumerating credential-store paths on a remote host as worth a human look, so it's called out here rather than folded in silently.
