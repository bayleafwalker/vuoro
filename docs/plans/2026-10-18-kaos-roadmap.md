# vuoro: KAOS-derived delivery plan

Status: operator-requested planning scope, 18 October 2026. Implementation, onboarding and qualification remain separate work.

This owner addendum implements the [two-year KAOS backcast](https://github.com/bayleafwalker/agentops/blob/main/docs/plans/agentops/2026-10-18-kaos-2028-roadmap.md) and preserves existing owner plans and October15/17 trust boundaries. Served references own execution status; this file records requirements. No new runtime, purchase or live deployment is implied.

## Delivery protocol

For each item: reconcile current source/observations and existing work; specify responsibility, sourcing and failure cases; implement/configure missing parts; qualify success/refusal/recovery; release/onboard under existing authority; verify use/outcomes/burden and document support/rollback/export. Source, released, deployed, field-qualified and accepted are distinct. Dependencies order work, without calendar promises.

## VU-K01 — Purpose, commitments and priorities

**Goal / feature / sourcing:** G01 / F01 / build. **Served item:** vuoro#2672.

**Current state / gap:** Product plan B/H identifies objectives and stewardship; work provider owns lifecycle. A general commitment capability is not qualified.

**Work:** Discover objective-to-work and continuing responsibility use cases; specify owner, success/stop criteria, assumptions, review triggers and dependencies; implement the smallest contract through the existing work provider; expose amend/stop and bounded impact reads.

**Predecessors:** AO-K02

**Acceptance:** An abandoned objective can stop dependent future work without erasing history; an assumption change lists affected decisions and unknown links; household semantics remain in HLA; no universal scheduler or automatic reopening.

## VU-K08 — Commitment economics

**Goal / feature / sourcing:** G08 / F08 / provision+adapter. **Served item:** vuoro#2678.

**Current state / gap:** Product direction distinguishes commitment accounting from provider hard stops and delayed alerts.

**Work:** Inventory spend controls by provider and execution route; bind one shared commitment budget to attempts; account known/unknown cost and enforcement delay; expose reservations, residual exposure and cancellation consequences.

**Predecessors:** VU-K06, DC-K01

**Acceptance:** Concurrent attempts do not each receive the full commitment budget; an alert is never labelled a hard cap; missing bills stay unknown; tested cancellation states explain in-flight work.

## Boundaries

This adds no effect authority. Execution and model choice remain native; protected effects retain their owners; content never grants permission. Qualify existing products before duplicating them. Preserve original evidence, explicit unknowns, human domain acceptance and current source/live distinctions.
